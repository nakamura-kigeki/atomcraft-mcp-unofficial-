# VERSION-NOTES.md — MCP利用者向けバージョン差分ノート

**この文書は CRI Atom Craft の公式変更履歴の代替ではない。** 公式変更履歴は
Ver.3.41系〜Ver.3.57系だけで120回以上のリリースを含む網羅的な記録だが、ここではその中から
**本 MCP サーバー(21ツール)の利用に関係する差分だけ**を独自の基準で抜き出し、
再構成している。GUIだけで完結する機能(キーボードショートカット、ツリーの色表示、
検索ウィンドウ、レベルメーター、外部プラグイン連携等)や、Robot API経由で触れない
不具合修正は原則として載せていない。完全な変更履歴が必要な場合は出典節を参照すること。

## この文書の読み方

- 節は**バージョン降順**に並んでいる。自分が使っている Atom Craft のバージョンより
  新しい節に書かれている概念・機能は、自分の手元のツールにはまだ存在しない。
- 「廃止・削除」の記載だけは逆で、自分のバージョンより新しいところで廃止された機能は
  自分の手元にはまだ残っている(アップデートすると消える)。
- Ver.3.42系・Ver.3.49系・Ver.3.53系は欠番(公式変更履歴上、当該バージョンのリリースが
  存在しない)。3.41→3.43、3.48→3.50、3.52→3.54と直接ジャンプする。

## MCPツールに影響する変更(バージョン降順)

### Ver.3.57系(2026-05-13〜2026-06-24)

- ビート同期情報の分子の上限値を128に変更(Ver.3.56.01でいったん32に修正されていたのが再拡大)
- スクリプトプラグインの Python 3.7 / 3.8 / 3.9 を廃止し、3.10 / 3.11(Ver.3.55.00〜)のみに一本化

### Ver.3.56系(2025-09-22〜2026-02-24)

- キューの再生モード「プレイリスト」を「繰り返し再生」に名称変更し、「繰り返し再生回数」
  項目を追加(該当フィールドの enum 値・名称が変わっている点に注意)
- 「ビルドに含めない」の設定項目名を「ビルドに含める」に変更。**意味が反転する名称変更。**
  設定値自体はプロジェクトファイル上で変わらないが、GUI上の表記・項目名が真逆になる
- 全体設定・キューシートに「ユーザーデータ」フィールドを追加(`atomcraft_get_property` /
  `atomcraft_set_property` で新たに扱えるフィールドが増えた)
- ビート同期情報の分子の上限値を32に修正(Ver.3.56.01。Ver.3.57系で再び128に拡大)

### Ver.3.55系(2025-04-01〜2025-09-11)

- ロボットのローカル実行が Python 3.10 / 3.11系に対応(重要な下限バージョン表を参照)
- **ミキサー Version 2 に対応**。複数の出力バス作成、4〜7次までの Ambisonics、
  32/64/128chの Object-Based Audio に対応する大型機能。Ver.3.52.00で「DSPバス設定」から
  改称された従来の「ミキサー」とは別建ての新機能
- トラック・ウェーブフォームリージョンに任意のバスマップを設定する機能を追加
- AISAC/オートメーション編集で、ポイントのX軸位置に関わらずY軸編集が行えるように変更
- (Ver.3.55.02)ロボットで、パラメーターパレットの「プレーヤーフェーダー」操作に対応
- (Ver.3.55.10)`create_workunit` がワークユニットサブフォルダーへの作成に対応

**既知不具合(この範囲で修正)**
- `copy_object` でAISAC/オートメーションの**ポイント**がコピーできない不具合。
  Ver.3.47.00〜Ver.3.55.02で発生、Ver.3.55.03で修正。
- ロボット関数の引数に日本語などマルチバイト文字を使用すると正しく処理されない不具合。
  Ver.3.47.00〜Ver.3.55.02で発生、Ver.3.55.03で修正。

### Ver.3.54系(2024-09-25〜2025-02-13)

- AISAC・オートメーションのバスセンドグラフ1〜8で任意のバス名指定に対応
- 再生パラメーターアクションに「バスセンド」タイプと「センド先バス名」を追加

## UNSUPPORTED_VERSION エラーとの関係

本リポジトリの新機能ツール(`atomcraft_preview` の新3アクション、`atomcraft_manage_beatsync`、
`atomcraft_bulk_property`)は、実際のAPI呼び出しの前に `versioning.require_feature` による
二段構えのゲートを通す。

1. **関数存在チェック(`hasattr`)** — 接続先のAtom Craft本体ではなく、`robot-path` が指す
   Robot Python側に対象関数が実際に存在するかを確認する。存在しなければ
   `UNSUPPORTED_VERSION` で確実にブロックする(`probe: "callable_missing"`)。これが実質的な
   防波堤になる。
2. **バージョン下限チェック** — `get_tool_version`(Ver.3.46.04で追加、上記参照)で取得した
   接続先バージョンが上表の `MIN_VER` 未満であれば `UNSUPPORTED_VERSION` で返す
   (`probe: "version_too_old"`)。バージョン取得に失敗した場合はブロックしない(fail-open)。

確度が「推定」の関数について `MIN_VER` を実際の初出バージョンより意図的に低く設定している
のは、バージョン比較だけでは確実に機能を止められない代わりに、関数存在チェックの方を
実質的な防波堤として機能させるための安全側の設計である。したがって、レガシーバージョンの
Atom Craft に接続してこれらのツールが `UNSUPPORTED_VERSION` を返した場合、エラーの
`details.probe` を見れば「バージョンが低いと判定されたのか」「そもそも関数が存在しない
(=`robot-path` が古い Python を指している可能性)のか」を区別できる。
